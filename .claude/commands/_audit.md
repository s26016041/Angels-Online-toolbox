# _audit（全專案稽核）— 每個功能都驗一遍、把「改版會壞」的寫法補掉、順手抓 bug

跟 `/_patchCheck` 的差別：那支是**官方改版後的急救**（哪裡壞了、怎麼修好）；
這支是**平時的體質檢查**（哪裡遲早會壞、哪裡寫得不夠穩、哪裡有 bug）。
沒有改版也可以跑，跑完應該留下「已修的」與「排好序的待辦」。

**使用者已授權：可以用他現在開著的天使之戀分身做確認。**
⚠ 但動作類（真的打怪／賣東西／換頻道）還是要先講一聲再動。

---

## 鐵律：不能弄壞功能

每一次改動之後**都要**把這串跑完才算數（有幾台分身就驗幾台）：

```
py tools\patch_doctor.py      # 位址層
py tools\verify_offsets.py    # 偏移層（不變量）
py tools\tab_check.py         # 逐分頁讀取
py tools\recheck_tables.py    # 查表＋setting
py tools\smoke_ui.py          # 10 個分頁建得起來
```

★ 改之前先**量一次基準**（舊寫法的輸出），改完拿新舊比對 —— 「一致」是
唯一能證明沒弄壞的證據。2026-08-11 改 `channel.count()` 就是這樣做的：
先五台實測「全掃 vs 伺服器清單」兩條路都回 5，才敢換。

## 1. 覆蓋率：哪些資料查詢還不是「改版不會壞」的方式

```
py tools\coverage_audit.py        # 開著遊戲；離線用 --image
```

它盤四件事，照 CLAUDE.md 的資料來源優先序（記憶體 > AOB > 資源包抄本）：

| 項 | 目標 | 沒到位的處理 |
|---|---|---|
| ① 位址 | **100%** 在 `locate.SIGS` | 一定要補；沒有例外 |
| ② 結構偏移 | AOB 特徵（`kind="off"`）> 有不變量會大聲 > 沒保護 | 見下面的判斷順序 |
| ③ 寫死的遊戲資料 | 記憶體有同一份就**別抄資源包** | 見 `reports/table_recheck.txt` 的 41 張表 |
| ④ 呼叫版面 | 每支 fn 的 `ret N` 存基準，改版後 diff | 變了就去看那支函式 |

### 偏移要不要做成特徵？判斷順序

1. **遊戲自己有沒有用那個偏移的程式碼**？有 → 做 `kind="off"` 特徵，
   從那道指令的 disp32 讀回來（`player.VT_OFF_FROM_MGR`、`quickbar.TABLE_OFF`、
   `entity.OFF_TARGET` 都是這樣）。⚠ pattern 裡那個 disp32 要自己寫 `??`。
2. 找不到唯一的指令錨 → 退而求其次，在 `verify_offsets.py` 加一條**不變量**
   （值域、兩條獨立的路要對上、跟另一個來源交叉比對），並且**把它加進那支的
   `COVERS`**，否則覆蓋率報告會繼續把它算成沒保護。
3. 兩者都做不到 → 在常數旁邊寫清楚「為什麼不行」與「壞掉會怎樣」。
   **沒有註解的裸偏移一律當債。**

⚠ 已知不算債的：`SCRATCH_OFF`（那是我們自己注入緩衝區裡的位置，跟遊戲無關）、
`injector.CODE_LO/HI`（範圍界線）、`MAX_/MIN_/LIMIT_` 開頭的上限值。

## 2. 功能驗證：每個分頁都真的能用

`tab_check.py` 驗**讀取**，但讀得到 ≠ 做得到。動作層目前**沒有工具**，
要手動確認（先跟使用者要授權）：

| 功能 | 硬證據 | 副作用 |
|---|---|---|
| 掛機出手 | 設目標 → `quickbar.use` → **怪的血下降**或 MP 真的扣 | 打一隻怪 |
| 走位 | `WALK_FN` → 座標真的變 | 移動幾格 |
| 自動登入 | 登入畫面 → 進遊戲，視窗標題出現帳號 | 佔用一台 |
| 換頻道 | 標題分流變 | 斷線重連 |
| 趴趴GO | 場景編號變 | **角色被丟走** |
| 賣／兌換／領獎／分解 | 只驗「送得出去、遊戲有反應」 | ⛔ 別真的跑，會消耗東西 |

⚠⚠ **`quickbar.use()` 回 True 只代表「排進指令槽」**，不代表遊戲真的做了事 ——
2026-08-11 就是這樣：回 True、MP 不扣、什麼都沒發生。**只認血量或 MP。**

## 3. 抓 bug：先照這張「這個專案實際踩過的坑」掃一遍

不是泛泛的 code review —— 下面每一條都在這個專案真的發生過，而且**症狀都跟
根因離很遠**。掃的時候一條一條對著找：

| 坑 | 長什麼樣 | memory |
|---|---|---|
| 「讀不到」被說成「沒有」 | 藥水用完／沒有獎勵券／沒有回程道具（**復發五次**） | `bag-false-empty-guards` |
| 讀得到 ≠ 還是它 | 物件搬家後舊位址照樣讀得到，不驗就安靜拿垃圾 | `stale-address-identity-check` |
| **寫**之前沒驗位址 | 拿舊位址寫 1 → 把遊戲 Lua UI 弄壞 | `patch-doctor-command` |
| 舉了沒放的閂 | Qt 吞例外 → 旗標永遠是 True → 功能永久卡死 | `frozen-tick-state-machines` |
| 被 early return 餓死的狀態機 | 連自己的逾時保險都不會響 | 同上 |
| 暫時性失敗設了上限 | 使用者要求：槽忙／背包沒變要**無上限重試**，出口是「暫停」鈕 | `transient-failure-auto-retry` |
| 量測工具自己把數據弄假 | 跨來源比對用了幾秒前的快照 → 假失敗 | `memory-re-pitfalls` |
| Qt 的坑 | 高頻刷新 clear() 重建、ResizeToContents 凍死、Qt6 拿掉的列舉 | `qt-ui-pitfalls` |
| 同一個位址寫兩份 | 一份會跟上改版、另一份不會，而且沒人會警告 | CLAUDE.md |

★ 改完一定要跑 `py tools\smoke_ui.py`（`py_compile` 抓不到 NameError，
Qt 訊號槽會吞例外讓測試假通過）。

## 4. 有沒有更穩的寫法（只在「能證明等價」時才改）

判斷標準只有三條，缺一不改：

1. **更少的失效面**：全掃 → 指標路徑、抄資源包 → 讀記憶體、寫死 → AOB。
2. **失效時更安全**：安靜做錯 → 大聲停用／安全退化。
3. **能證明等價**：舊寫法與新寫法在**現在這五台**上輸出一致。

已完成的例子（可以照抄這個做法）：

* `channel.count()`：全記憶體掃描（35~58ms，最壞 0.3~1 秒且卡 GUI 執行緒）
  → 先走 `login.servers()`（0.0~1.1ms），全掃留當退路。
  **五台實測兩條路都回 5** 才換。順帶消掉「伺服器記錄版面寫兩份」。
* `monsters.INDEX_PTR_RVA`：位址寫死在特徵裡當錨 → 用**字串內容**（`Npc`）當錨。
* `player.STATS_FROM_MGR`：寫死偏移 → `kind="off"` 特徵自動跟上。

⛔ **不要為了漂亮而改。** 這個專案的每一段怪寫法幾乎都有血淚註解，
動之前先讀那段註解與對應的 memory；沒讀懂就別動。

## 5. 收尾

* 一次 commit 一件事，訊息寫清楚「原本會怎麼壞、改成什麼、怎麼證明沒弄壞」
* 沒做完的留成**排好序的待辦**（寫進 memory，別留在對話裡）
* 要發版走 `/_pushReleases`（⚠ 建 Release 前要先問過使用者）
